# Sic Bo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a small single-player Sic Bo game with Big, Small, Odd, Even, exact-total, and Any Triple bets, using local pure rules and the existing public wallet/session seams.

**Architecture:** Keep Sic Bo self-contained under `src/lib/sic-bo/` with pure dice/rules/state files and one browser client. The Astro route renders the existing Art Deco UI conventions while authenticated play submits one net round settlement through the shared wallet gate; guest play remains local. Do not refactor Craps or create generic dice/betting infrastructure.

**Tech Stack:** Astro, TypeScript, Bun tests, Playwright, existing Arcturus `public-game-session`, wager validation, wallet settlement, game statistics, and Art Deco UI primitives.

## Global Constraints

- Support only Big, Small, Odd, Even, exact total 4–17, and Any Triple.
- Big/Small/Odd/Even lose on every triple.
- Use three client-side six-sided dice; no server-authoritative outcome.
- Keep all payout logic local to `src/lib/sic-bo/`.
- Use one logical wallet settlement per completed roll.
- Reuse existing wallet retry/reset behavior; do not add queues, timers, persisted retries, or automatic backoff.
- No database migration or new schema.
- No generic dice-game, betting-board, paytable, game-session, or plugin abstraction.
- Guest play never calls `/api/wallet/settle`.
- Breaking cleanup is allowed; no compatibility layer is required.

- [ ] **Step 3: Implement the minimal state machine**

Use only two phases:

```ts
export type SicBoPhase = 'betting' | 'complete';
```

Keep selected bets in a plain record/map keyed by `SicBoBetKey`. `setBet()` replaces the value for a key. Compute affordability using all other selected bets plus the candidate amount.

`roll()` must:

1. verify phase is `betting`;
2. require at least one selected bet;
3. validate current total stake;
4. generate one roll;
5. resolve every selected bet;
6. subtract total stake and add gross return;
7. store a complete immutable-style result;
8. switch to `complete`.
