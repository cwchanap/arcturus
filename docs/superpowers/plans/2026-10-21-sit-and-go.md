## Task 1 — Minimal pure rules

**Files:** `sitAndGo.ts`, `sitAndGo.test.ts`

- [ ] Test blind levels derived from 1-based existing `handNumber` (hands 1/5/6/10/11/16/21 and cap); do not maintain another counter.
- [ ] Test next-funded seat rotation including gaps, wrap, full table and heads-up button = SB. No separate preflop/postflop helper; `getNextPlayerIndex` already covers action order.
- [ ] Test human's final place from funded survivors and simultaneous busts with larger/equal starting stacks. No full finish-order history.
- [ ] Implement only fixed setup constants, `levelFor(handNumber)`, a small next-funded/button/blinds helper and `humanPlace(...)`. Keep signatures small.

## Task 2 — Mode and local-play reuse

**Files:** `PokerGame.ts`, `PokerGame.test.ts`, `poker.astro`

- [ ] Parse literal `?mode=sng` server-side; unknown values default cash. Set `data-poker-mode` and read mode once in `PokerGame`.
- [ ] Add `playsLocally = isGuestMode || mode === 'sng'` and replace the relevant guest-mode checks (start balance, per-hand settlement, gate blocking, event dispatch, LLM configuration/decision, `adoptAccountBalance`) with this reuse. Ensure **no** SNG wallet calls even for authenticated users.
- [ ] Guest bankroll load/persist and rebuy must remain **cash-only** (`isGuestMode && mode === 'cash'`) at all relevant call sites: constructor, beforeunload, `persistGuestBankroll`, hand settlement and rebuy button/action.
- [ ] Initialize six 500-chip local stacks in SNG, ignoring account/wallet cash settings. Built-in AI only; no LLM overlay/network requests.
- [ ] Server-side page markup must render `#poker-missions` only when `!gameSession.isGuest && !isSng`; JS then naturally skips `initPokerTableMissions` and mission claim `onBalance`. Guard direct `adoptAccountBalance` too.
- [ ] Test guest and authenticated SNG with account balance unavailable or nonzero, a guest's existing persisted cash bankroll, and cash default behavior. All SNG stacks remain 500 before play; no persistence/wallet calls or cash stack adoption.

## Task 3 — Shared all-in runout, funded-seat rotation, hand lifecycle

**Files:** `PokerGame.ts`, `PokerGame.test.ts`, `sitAndGo.ts`

- [ ] **First commit in this task:** reproduce frozen all-in human dealer and illegal folded-AI dealer action in existing cash engine; test side pots and legal preflop call/fold rights.
- [ ] After revealing a new **unbet** street in `nextPhase`, if `getPlayersWhoCanAct(players).length < 2`, schedule the next street/showdown via existing `scheduleTurnTransition`. In `processAITurn`, when `!canPlayerAct(currentPlayer)`, safely reconcile/advance instead of making a decision. Handle preflop with no actor after blinds. Do not automatically skip an unresolved all-in preflop call/fold.
- [ ] Use one next-funded dealer/blind rotation for cash and SNG, skipping busted seats, with heads-up button = SB. After setting funded positions, reuse `getNextPlayerIndex` for preflop action after BB and postflop after dealer.
- [ ] Preserve six array indices; fold eliminated seats immediately after each new-hand reset, deal them no cards, skip their actions/blinds. Preserve current-hand all-in side-pot eligibility until awards.
- [ ] SNG `dealNewHand` bypasses cash's positive-wallet human restore, AI auto-rebuy and pending chip reset. Use derived SNG blinds in `postBlind`, legal raise and toolbar; cash mode retains its configured blinds.
- [ ] Focused tests: survivors `[0,2,5]`, heads-up `[0,5]`, nonadjacent dead button/SB/BB, short-stack blind all-in, zero-stack human with positive wallet, no rebuy, no all-in deadlock and no phantom folded-seat bets.
- [ ] **Seeded whole-tournament simulation** using `mockTrackedTimers` (existing `PokerGame.test.ts`) and deterministic `aiRandom`, driving human check/call/shove. After each hand assert 3,000 awarded chips, no further folded-seat bets, busted seats never act, and every pending state either has a timer, awaits legal human input or has completed. Require a terminal human win/bust within a generous bounded number of hands. Across run assert **zero** wallet calls, **zero** `POKER_HAND_SETTLED_EVENT` emissions, and unchanged `poker_session_stats`. Keep focused tests for unusual edge cases rather than relying solely on simulation.

## Task 4 — Terminal place and cash-stat isolation

**Files:** `PokerGame.ts`, `PokerGame.test.ts`

- [ ] At the existing final pot award, compute survivor count and simultaneous busts from `handStartStacks`. If human is zero finish with their place; if human is sole survivor display 1st. No complete finish-order list.
- [ ] Stop any queued/manual/auto deal at terminal state. Retain the existing 5-second hand-result hold and auto-deal preference for ordinary hands; no need to disable them globally.
- [ ] `playsLocally` skips **all** SNG hand/terminal wallet settlement, pending gate and per-hand settled events. Keep `finalizeActiveHandBeforeDeal` harmless for SNG; cash settlement/reset/retry remains unchanged.
- [ ] Skip `recordHand`, `saveSessionStats` and `renderSessionStats` in SNG hand results. Test an entire SNG leaves cash session localStorage, D1/account stats and mission event emissions untouched.
- [ ] Regression-test double finish, scheduled auto-deal firing after terminal, victory/bust rank, and cash settlement after a fresh cash navigation. No terminal receipt, idempotency logic or in-place reset.

## Explicit cuts / caveats

- Refresh/new tournament restarts; no save/resume.
- Existing `MAX_BET` cap stays; no fully generalized no-limit raise redesign.
- HPA-172's `sit-and-go-champion` feat and any distinct authenticated terminal result/receipt are deferred. That later ticket must explicitly avoid mixing tournament wins/hands into cash Poker D1 stats and `handsPlayed` missions.
- No second engine, account buy-in/prizes, multiplayer, leaderboard, assets, generic tournament framework or AI-only completion after human bust.
