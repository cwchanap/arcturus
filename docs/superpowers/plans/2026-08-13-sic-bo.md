# Sic Bo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a small single-player Sic Bo game with Big, Small, Odd, Even, exact-total, and Any Triple bets, using local pure rules and the existing public session/wallet seams.

**Architecture:** Keep Sic Bo self-contained under `src/lib/sic-bo/`. Dice, payout predicates, bet-slip validation, and round state are pure game code. The browser client composes `public-game-session` with the existing wallet settlement gate/recovery controls; guest play remains local. Do not refactor Craps or add another wallet controller/framework.

**Tech Stack:** Astro, TypeScript, Bun tests, happy-dom, Playwright, existing `public-game-session`, wallet settlement/recovery, and game statistics.

## Global Constraints

- Support only Big, Small, Odd, Even, exact total 4–17, and Any Triple.
- Big/Small/Odd/Even lose on every triple.
- Use three client-side six-sided dice with injectable randomness.
- Use closed `SicBoBetKey` string keys.
- Valid per-position amounts are only `[1, 5, 10, 25, 50, 100]`.
- Re-clicking the currently selected denomination clears that bet; **Clear bets** clears the whole slip.
- Use the selected Paytable A odds: 4/17=50, 5/16=18, 6/15=14, 7/14=12, 8/13=8, 9–12=6, Any Triple=24.
- Do not call `validateBet()`.
- `SicBoGame.getRollError()` owns Roll eligibility, but the client consults it only while phase is `betting`.
- One wallet settlement per completed authenticated roll; Retry reuses the exact command/ID.
- Guest play never calls `/api/wallet/settle`.
- Authenticated wallet-mutating E2E tests use `createIsolatedPage()`.
- No schema, server dice, shared dice/betting/paytable framework, settlement controller, retry queue, or compatibility layer.

- [ ] **Step 5: Implement the two-phase state machine**

```ts
export type SicBoPhase = 'betting' | 'complete';
```

`getBetError()`:

```ts
getBetError(key: SicBoBetKey, amount: number): string | null {
  if (this.state.phase !== 'betting') return 'Bets can only change before rolling';
  if (!SIC_BO_CHIP_DENOMINATIONS.includes(amount as (typeof SIC_BO_CHIP_DENOMINATIONS)[number])) {
    return 'Choose a valid chip denomination';
  }
  const otherStake = this.getTotalStake() - (this.state.bets[key] ?? 0);
  if (otherStake + amount > this.state.balance) return 'Selected bets exceed available balance';
  return null;
}
```

`getRollError()`:

```ts
getRollError(): string | null {
  if (this.state.phase !== 'betting') return 'Start a new round before rolling again';
  const stake = this.getTotalStake();
  if (stake === 0) return 'Place at least one bet';
  if (stake > this.state.balance) return 'Selected bets exceed available balance';
  return null;
}
```

Do not call `validateBet()`.

- [ ] **Step 6: Implement Roll and lifecycle**

`roll()` checks phase/`getRollError()`, rolls once, resolves each selected bet, sums gross return, sets `netDelta = grossReturn - totalStake`, updates balance, stores result, and switches to `complete`.

`resetRound()` keeps bets. `clearBet()` / `clearBets()` only mutate in `betting`. `setBalance()` rejects negative/non-finite balances and truncates to whole chips.

## Risks to keep visible during implementation

- **Primary action phase:** `getRollError()` must only decide whether `Roll` is enabled; applying it to the complete phase deadlocks **New Round**.
- **Wallet delta ceiling:** the current closed 100-chip position amount limits the maximum positive round to 5,200 chips. If denominations or odds are expanded later, re-check against the wallet's 1,000,000 settlement sanity guard.
- **Retained slip after balance adoption:** a lower server balance can make kept bets unaffordable; per-position clear and **Clear bets** must remain usable in betting phase.
