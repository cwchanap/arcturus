**Modify (focused)**

## Task 1 — Pure tournament rules and tests

**Files:** `sitAndGo.ts`, `sitAndGo.test.ts`

- [ ] Write failing table-driven tests for initial six 500-chip stacks, level boundaries at hands 1/6/11/16/21, and level cap.
- [ ] Add tests for dealer/blind/preflop/postflop selection for full table, nonadjacent funded seats, and heads-up; include heads-up button/SB first preflop and BB first postflop.
- [ ] Test start-of-hand stack comparison and placement when one or multiple seats bust, including a tie; verify elimination is applied only after payouts.
- [ ] Implement small pure helpers: `getSngBlinds(completedHands)`, `getFundedSeatIds(players)`, `getNextFundedSeat(ids, previousDealer)`, `getSngPositions(ids, dealer)`, `getSngFinishPlace(beforeStacks, afterStacks, humanId)`; use existing `Player` type. Helpers must not mutate inputs.
- [ ] Run `bun test src/lib/poker/sitAndGo.test.ts`. Ensure no duplicated card-hand evaluator or pot code was added.

**Expected contract:** Return only the funded-seat positions actually needed by `PokerGame` at the relevant hand/street transition. Avoid committing to a five-field `SngPositions` API upfront; a couple of small functions or fields is sufficient. `getNextPlayerIndex` filters action eligibility and must **not** be used for dealer/blind selection.

## Task 2 — Enter the SNG mode without touching cash chips

**Files:** `poker.astro`, `PokerGame.ts`, `PokerGame.test.ts`

- [ ] Add a link to `/games/poker?mode=sng` and a return-to-cash link. Read only literal `mode=sng`; unknown values stay cash.
- [ ] Pass mode through `#poker-root[data-poker-mode]`; let `PokerGame` select mode once at construction (not during a hand). No extra constructor dependencies required for cash callers.
- [ ] In SNG initialize local human/AI stacks to 500 and ignore `gameSession.initialBalance` **only for tournament stack display/play**. Preserve actual `guestMode` for knowing whether a final account receipt is allowed.
- [ ] Guard `PokerGame.adoptAccountBalance()` at entry: return `false` for SNG even when idle and the given balance is valid; mission-claim callbacks must never replace `players[0].chips` with account chips. Add a direct test that a mid-tournament external balance update is ignored.
- [ ] Disable `hasServerSyncedBalance` as a **start gate** for SNG, but never fake it for normal Poker. Do not read/write `poker` guest bankroll key during SNG.
- [ ] Snapshot AI choices at tournament start; disable LLM strategy and its no-key overlay for SNG, without changing persisted Poker settings.
- [ ] Unit-test independent starts for guest and signed-in users with zero/unavailable account balance and assert no hand-level `SettlementGate.settle` calls. Assert `adoptAccountBalance(9_999)` returns `false` and leaves the SNG human at their tournament chip count; repeat in cash mode to preserve the prior allowed idle adoption. Cash-mode tests remain unchanged.

## Task 3 — Hand participation, blinds, and no rebuy

**Files:** `PokerGame.ts`, `PokerGame.test.ts` (use `sitAndGo.ts` helpers)

- [ ] On new SNG hand, check tournament not over, find funded seats, move dealer by funded seats, snapshot blinds, and assign heads-up/full-table positions before posting.
- [ ] Retain original six array indices; after the normal reset mark zero-chip seats folded/ineligible. Deal hole cards only to funded seats. Never let excluded seats act or enter showdown.
- [ ] Explicitly bypass the existing `dealNewHand()` eliminated-human branch that replaces zero tournament chips with a positive server wallet balance, even if terminal flags are unexpectedly stale. A busted human cannot be resurrected. Add a regression test with human stack `0` and nonzero account balance.
- [ ] Apply SNG blinds to `postBlind`, min-raise calculations and toolbar; exclude settings-saved blind overrides, pending chip reset, cash-mode AI auto-rebuy and cash rebuy button.
- [ ] Ensure that after a street change the first actor is computed from funded seats; action traversal must skip folded/ineligible/all-in while showdown still includes current-hand all-ins. Do not reuse action-eligibility traversal as the funded-seat dealer/blind selector.
- [ ] Test survivors `[0, 2, 5]` and heads-up `[0, 5]` on consecutive button rotations, short blind/all-in cases, a busted dealer/SB/BB, and no-rebuy after an AI reaches zero.
- [ ] Verify `PokerGame` remains compatible with preexisting pot/side-pot/showdown tests; do not rewrite expected poker rules.

## Task 4 — Terminal state and single receipt

**Files:** `PokerGame.ts`, `PokerGame.test.ts`

- [ ] At the single final-award path in `finishHand`, increment completed-hand count once, capture pre-hand funded stacks, derive newly busted IDs **after** side-pot credits, and update rank/remaining count.
- [ ] If human busted: stop immediately with recorded finishing place. If only human funded: finish 1st. Otherwise enable manual Next Hand. Cancel pending auto-deal/turn timers when terminal.
- [ ] Leave `settleHand` and existing account/guest settlement logic intact for cash mode; make it a no-op during SNG hands. Never let `finalizeActiveHandBeforeDeal` settle a SNG hand. Guard the `presentHandResult()` block that calls `recordHand`, `saveSessionStats`, and `renderSessionStats` so SNG hands cannot contaminate cash-session metrics in localStorage.
- [ ] On terminal SNG result for authenticated users, use `buildPokerSettlementCommand(0, finishPlace === 1 ? 'win' : 'loss')` **once** (its existing ID and stats contract is sufficient; optional `netProfit` may stay omitted). Submit it through the existing gate. Do not send for guests or introduce another settlement builder.
- [ ] Retain the existing terminal command for retry, and never replace tournament-stack chips with `result.balance` in `adoptSettlementResult`. Handle pending/failed terminal receipt via the existing settlement gate/retry UI, without restarting a completed tournament.
- [ ] Test no more than one terminal call despite repeated clicks, timeouts, async retries, or duplicate finish invocation; verify the same settlement ID is used on retry. Test account balance is not assigned to SNG stack. Assert SNG `recordHand`/`saveSessionStats` are not invoked and preexisting cash stats are unchanged after a tournament hand.
- [ ] Keep HPA-172's `feats` addition as **future scope**; do not implement an achievements grant here.

## Explicit cuts / caveats

- Reload restarts; no tournament persistence. The final receipt is not guaranteed if the tab closes before successful submit, which is acceptable for the hobby MVP.
- Existing table max-raise behavior remains; full no-limit tournament raise redesign is not part of HPA-176.
- One zero-delta Poker stats round represents the whole event, not each hand. HPA-172 may later extend this terminal command with `sit-and-go-champion`; it is a separately scoped task/PR.
- No game-wide poker refactor, second poker engine, generic tournament library, stake/prize economy, ranked leaderboard, or AI art/SFX in this ticket.
