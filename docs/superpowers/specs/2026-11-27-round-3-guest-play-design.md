## 1. Poker timing contract

Retain configured per-rival delay Slow 1500–2500 ms, Normal 800–1500 ms, Fast 300–600 ms. On a foreground page, measure from a particular rival becoming actionable/Thinking until its recorded/visible action (not from a human click to a later human turn, which includes multiple rivals and streets). Use browser MCP timestamps from DOM observation / performance tracing, without shipping a debug API. In tests, use existing deterministic deck/AI seams and timer tests; do not change strategy RNG. Verify cash and SNG, all speeds, several consecutive rival turns and streets, all-in runout, and human controls. Capture configured sampled delay, actual action elapsed and time spent in strategy/UI via local test instrumentation. Target sampled delay plus at most 250ms foreground processing overhead per action on the test machine, with no unexplained multi-second pauses. Separately account for the explicit 1000ms street/runout transition and optional 5000ms auto-deal. Confirm a slow device/background tab is not a claim of guaranteed wall-clock SLA. If reproduction matches the contract, record the evidence and explain cumulative latency; make the settings help text explicit about per-action delay and additional street waits. If not, fix the smallest identified timer/render/strategy issue. No new Worker, timer framework, provider request for guests, or indiscriminate difficulty changes. Preserve cancellation tokens, stale callbacks, all-in/folded seat skipping, legal bets, and human-turn timer. Optional authenticated BYOK latency is separate from the built-in delay; do not claim provider response time is bounded.

## 2. Guest practice chip recovery

Use a common localized **Reset practice chips** action (with amount/this-game-only explanation) visible near the guest bankroll when it is below the existing default 1,000, but enabled only at a safe idle boundary. Explicit click restores the current game's guest balance to exactly 1,000 (not +1,000); normal balances still persist across navigation/reload, no automatic refill. This includes the reported Slots balance 5 even though minimum spin is 1. No reset above the default or while a wager/hand/reveal is in progress. Do not automatically place a bet/deal/spin when resetting. No account credit, settlement, achievements, stats, mission increments, ranked or Daily attempts; no shared guest funds across games.

Use `DEFAULT_GUEST_GAME_BALANCE`, existing `loadGuestBankroll` and `persistGuestBankroll`; keep eligibility and mutation in each current client/domain owner. A small shared UI binding/predicate and four-locale copy may be reused; callbacks recheck guest, cash mode, balance and safe boundary at click time. Existing games with `createPublicGameSettlementController` may use one focused guest-only reset method that adopts and persists balance and invokes their existing reset/render callbacks; legacy games use their current setters and render/persist seams. Do not move gameplay policy into wallet settlement or introduce a global state registry. Reset only the bankroll/round fields necessary to return to ready state; preserve settings, sound, locale and unrelated game keys. In-memory baseline, rendered amount and bet constraints agree immediately and survive reload. Storage errors remain best-effort, same as ordinary guest play.

| Current owner | Safe reset requirements |
| --- | --- |
| Poker `PokerGame.ts` | Adapt existing rebuy action/translation rather than add parallel buttons. Show on initialization and settled idle, including restored low balance; update both human stack and serverSyncedBalance (local baseline), persist; no auto-deal on reset; cancel pending auto-deal for reset without mutating tournament. Allow normal explicit deal afterwards. |
| Blackjack `blackjackClient.ts` | Idle/complete only; leave active split/double and unresolved dealer animation untouched; reset round through existing flow, sync bet constraints and local baseline. |
| Slots `slotsClient.ts`, Keno `kenoClient.ts` | No spin/draw or pending reveal; update domain balance, renderers, local baseline and wager limits. |
| Baccarat `pages/games/baccarat.astro` | No placed wager or dealing/reveal; offer reset inside existing insufficient overlay and in idle state, dismiss overlay on success. |
| Craps `pages/games/craps.astro` | Never discard live contract bets/point or odds. Reset only when no active bets, at a safe idle boundary, persist through existing session owner; clear/dismiss stale insufficient overlay. If bankroll is zero with active bets, ensure roll/resolve remains available without requiring new chips. If point alone remains, retain it or use existing legal fresh-table reset when no bets are at risk. |
| Roulette `rouletteClient.ts` | No bets or pending wheel reveal (guest domain settles before animation, so phase alone is insufficient); update both bankroll and `roulette-session:anonymous` via existing persist path so restored snapshots cannot overwrite reset. |
| Video Poker, Sic Bo, Three-Card Showdown, Pai Gow `client.ts` | Use current controller and domain setter, reset completed rounds only; staged wagers must be cleared legally first; do not discard held cards / pending arrangement / second-stage bets. |

Guard all callbacks against rapid repeats/stale UI; use current phase/animation flags, not speculative timers. Guest reset must never be exposed as account settlement recovery. Tests assert no relevant account API requests, and other game's balance remains unchanged.

## 3. Result feedback and rival speech

Keep the one pure `winTier` source and inclusive net thresholds from HPA-729 (5/20× resolved stake; poker 20/50 BB). The ticket's 275 gross pot does not establish a qualifying human net gain, and Craps total stake may differ from one Hard 8 bet. Add an actual fixed Craps resolved result (net +250, resolved stake 25 if possible via legal fixture; otherwise record actual stake and use an equivalent qualifying legal fixture) and Poker fixed net result. Existing game integrations are listed in [HPA-729](2026-11-17-big-win-celebration-design.md). Audit each caller's net/denominator and ensure exactly once on visible result, never replayed on hydrate, wallet retry, reset or loss/push. Existing E2E direct module import proves renderer only, not gameplay wiring. Add a small localized static Big Win + net amount label to the big tier (normal and reduced motion); retain huge ribbon, duration, click-through and reduced motion behavior; only lower thresholds if deterministic results show legitimate ordinary qualifying wins still fail for a measured reason (document a spec amendment rather than quietly widening). No stacking SFX; same mute preference and existing files. Test actual audio invocation with mute/unmute and reduced-motion; acoustic output on headless VM is not required.

For rival talk retain `rivalTalk.ts` event eligibility, priority and no hidden-card information. Preserve 50% for betting all-ins; change the single eligible end-of-hand reaction to guaranteed when quota permits (at most one end-of-hand reaction, max two total, one active, existing 2.5s display; reserve the second slot for end-of-hand if needed by allowing at most one betting bubble). This makes a qualifying result observable while still not reacting to every hand. Reuse existing localized lines and renderer; no extra events based on human losses or false bluff claims. Verify fixed rival bad beat, net-big-pot, bluff and SNG elimination from actual hand resolution; below-threshold, folded and uncalled-return cases stay silent. Check portrait overlap, hidden delta behavior and automatic cleanup. Ensure next hand and auto-deal do not leave stale bubbles.

## 4. Discoverability, auth boundaries and toast

- Shared `AppLayout.astro` retains Missions navigation and adds Shop in desktop navigation/footer with accessible narrow-width placement (avoid overflowing phone header). In cash Poker, a compact guest-only sign-in hint near the existing mission strip describes missions, badges/rings and table cosmetics, with links to the relevant pages. Do not render a fake mission meter or fake ownership. Fix mode pills: cash and Sit & Go links present, active mode visibly distinguished and `aria-current` correct; SNG notice and 500 tournament chips stay unchanged.
- Proposed visibility policy: `/missions` guest renders a concise sign-in preview explaining daily/weekly goals and rewards, not personalized targets/progress; `/shop` guest renders the existing static catalog names/images/prices with a single sign-in CTA and no purchase/equip controls. Reuse `CATALOG`, `SHOP_ITEM_IDS_BY_KIND`, existing translators and card layout; do not call D1 wallet/shop/mission reads in guest branches. Authenticated routes continue current reads, private no-store behavior and existing actions. Guest API auth remains unchanged, no account mutation endpoints become public. If existing redirect tests need updating, assert the new intentionally public preview instead of removing auth tests. Keep private multiplayer/profile/ranked restrictions.
- In `layouts/casino.astro`, mount account achievement toast only when an authenticated session exists; in `AchievementToast.astro`/ `achievement-toast.ts`, ensure idle markup truly hidden (e.g. hidden attribute plus appropriate reveal/cleanup) and does not announce the generic title before a named grant. Keep auth queue semantics, localized real names/icons, and no duplicate grants. Do not add a guest achievement service.
- Use existing `defineMessages` typed dictionaries for EN, zh-Hant, zh-Hans, ja, current Art Deco controls/links and existing assets. No redesign of game layouts.
